================================================================
CATEGORY HIERARCHY — HOW TO CHOOSE A LEVEL
================================================================

Three levels, coarse to fine: class (8) → award_group (37) → source_name (66).
A category row has all three. Pick the level that matches the question's
specificity:

1. The question names a specific award ("Best Picture", "Cinematography",
   "Directing") → filter on award_group. Map colloquial names first: Best
   Actor/Actress → Actor/Actress -- Leading Role; Best Supporting
   Actor/Actress → Actor/Actress -- Supporting Role; Best Director →
   Directing; Best Original Song → Music (Song); Best Score → Music
   (Scoring).
2. The question asks about a broad family ("acting awards", "the technical
   categories", "music awards") → filter on class.
3. The question asks how a category's name/wording changed over time
   ("how has the Cinematography category name changed?") → filter on
   award_group (it already spans every historical source_name for that
   award — see TRAP below) and GROUP BY raw_category to see the wording
   across ceremonies.
4. The question names one specific historical/defunct variant exactly
   ("what was CINEMATOGRAPHY (Black-and-White)?") → filter source_name to
   that exact string.

When unsure between class and award_group, prefer award_group. It is more
precise and less likely to sweep in unrelated categories.

TRAP: an award_group can bundle source_name rows two different ways. If the
variants are chronologically exclusive (one ends where the next begins, or
a fixed-span split reunifies into one name), it's the same award renamed
or split — filter award_group, which spans every era (e.g.
Cinematography's Black-and-White/Color split, ceremonies 12–39, merged
into plain CINEMATOGRAPHY). If two or more source_names are still both
active today (max ceremony ~98), they're genuinely different awards
sharing an umbrella — filter source_name to isolate one (Writing's Adapted
vs. Original Screenplay, both awarded yearly). Unsure? Prefer award_group,
same default as class vs. award_group above.

TRAP: class = 'Directing' includes 'Assistant Director', a defunct and
unrelated award. For any question about film directors, use
award_group = 'Directing'.

TRAP: 'Best Picture' is an award_group value, not a class. Early Best Picture
awards went to studios, so nominees may be kind = 'company'.

================================================================
IDENTIFYING FILMS AND PEOPLE
================================================================

Film titles are NOT unique. Two different films are titled "Titanic" (1953,
1997). Always JOIN and GROUP BY on film_id, never on title. When a query
returns films, include films.release_year in the SELECT so the user can tell
them apart — even if they did not ask for it.

Person names are NOT unique either (two different "Chris Cooper" rows —
the actor; an unrelated technical-award recipient). Always include
people.person_id and birth_year when returning people; birth_year may be
NULL.

Name and title lookups from user input should use LIKE with wildcards, not =.
Users will not match capitalization or punctuation exactly. Example:
  WHERE p.name LIKE '%Daniel%Day-Lewis%'

TRAP: a surname-only LIKE pattern can catch unrelated namesakes — this
database has real multi-member families (Coppola: 4; Huston: 5; Spielberg:
2). Match the full name with a wildcard between parts when the question
gives one — e.g. '%Steven%Spielberg%' for "Steven Spielberg", not
'%Spielberg%' (which also matches his sister Anne Spielberg). Surname-only
is fine only when that's literally all the question gives ("Coppola").

people contains both individuals (kind = 'person') and organizations
(kind = 'company' — studios, technology firms). Add kind = 'person' when the
question is about individuals. Do NOT add it when the question is about
studios or companies.

TRAP: kind = 'company' rows are almost entirely early-Hollywood-era
credits (studios named as Best Picture nominees decades ago) plus a
handful of technology firms (Sci-Tech recipients like Avid Technology,
Arri). Warner Bros. and Disney have rows under several historical name
variants; modern production companies generally do not — Pixar, Marvel,
and Netflix all have zero matching rows despite their films having real
wins. A kind = 'company' name search returning no rows does NOT mean the
company has zero real-world wins — it means this schema doesn't credit
that company as a nominee (its films' wins go to individual producers or
directors instead). Say so explicitly; do not report a bare zero as the
answer.

"Who won Best Picture" defaults to identifying the FILM, via
nomination_films — not the producers. Only bring in nomination_people /
people when the question explicitly asks for the people or companies
credited (e.g. "who produced the film that won", "which studio won Best
Picture in the 1930s"). If you do query people for a Best Picture win, do
NOT filter kind = 'person' — early winners were studios, and filtering to
persons would silently drop them.

================================================================
JOIN PATHS
================================================================

Directors come from film_directors, not from nominations. "Who directed X" is
answered by films → film_directors → people. A director who was never
personally nominated still has rows in film_directors. Do not derive directors
from the Directing category — that only finds nominated directors.

Not every film has a director row. film_directors covers 5,189 of 5,265
films. An INNER JOIN to film_directors silently drops the rest — including
Wings (1927/28), the first Best Picture winner. Use LEFT JOIN when the
question is about films and the director is supplementary; use INNER JOIN
only when the question is fundamentally about directors.

People on a nomination come from nomination_people, not official_name.
official_name is a display string. A nomination often has several people, and
matching on official_name would miss them.

1,280 nominations have no film. These are citation-based awards (Sci-Tech,
Honorary, Thalberg, Hersholt) plus a few gaps in regular categories. An INNER
JOIN to nomination_films silently drops all of them. Use INNER JOIN when the
question is clearly about films; use LEFT JOIN when the question spans all
award types ("how many Oscars did X win?").

Counting: a JOIN to nomination_people or nomination_films multiplies rows.
COUNT(*) after such a join counts links, not nominations. Use
COUNT(DISTINCT n.nomination_id) when you mean nominations.

The same fan-out duplicates rows in a plain listing or ranking query, not
just COUNT. 18 nominations (all ceremonies 1–3 and 8, the era of citing a
body of work rather than one film) link to more than one film — e.g. Janet
Gaynor's sole win covers 7th Heaven, Sunrise, and Street Angel in one
nomination. A "who/which" query joined through nomination_films will list
that winner once per film. Add DISTINCT on person_id (or nomination_id)
when the question wants one row per person or win.

================================================================
ANSWERING BEHAVIOR
================================================================

If the schema cannot answer the question, say so plainly instead of
approximating, and name the missing data. The database has no genre, plot,
country, language, budget, or box-office data. "Which war films won Best
Picture" and "show me Japanese films that won" are not answerable — do not
substitute a proxy such as guessing nationality from original_title.

Default to all-time scope. "Who won Best Picture?" means every winner unless
the question names a year or says "most recent" / "latest."

Interpret a bare year as year_label, the eligibility year. "The 2023 Oscars"
means year_label = '2023' — ceremony 96, the films of 2023. Do not convert to
the year the ceremony was held.

Limit large result sets: add LIMIT 20 (and say so) if a question could
return hundreds of rows and the user did not ask for all of them. When a
LIMIT actually truncates a chronological list, order newest first (ORDER
BY ceremony DESC) so the visible rows are the recent ones. When returning
the complete set instead — no LIMIT, because the user asked for "all" or
the table is small — order chronologically ascending, the natural reading
order. Never apply newest-first to a ranked result (most-nominated, most
wins, youngest...) — that would overwrite the question's own ranking
ORDER BY.

Prefer readable output. Return names and titles, not bare IDs — but keep the
disambiguating id/year columns described above. Use COALESCE(title_zh, title)
and COALESCE(name_zh, name) only when the question is about Chinese titles or
names; English is the default display, because title_zh is NULL for ~75% of
films and mixing languages in one column is harder to read.
